## Phase Goal

**As a** prospective library user, **I want to** self-register with my email and password, verify my email, and then log in, **so that** I get an authenticated session that persists across browser restarts.

<objective>
Deliver the authentication vertical slice end-to-end: a React register page → FastAPI `/auth/register` → unverified User + verification token → email link → `/auth/verify-email` → React login page → `/auth/login` issuing a 24h JWT stored in a persisted Zustand store. Email verification is strict: login is BLOCKED (not warned) until verified (D-01).

Purpose: Authentication must precede every protected endpoint; it cannot be bolted on later without touching every route (PITFALLS C4). Implements AUTH-01 and AUTH-02.
Output: Working register → verify → login → session flow with JWT in localStorage and `/auth/me` profile retrieval.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /api/auth/* | Unauthenticated credentials and registration data enter here |
| JWT bearer → get_current_user | Token-based identity assertion crosses into authorized context |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Spoofing | Login / JWT forgery | mitigate | HS256 JWT signed with env JWT_SECRET; identity = `sub` claim verified against DB on every request (get_current_user) |
| T-02-02 | Information Disclosure | Password storage | mitigate | Argon2 via pwdlib; plaintext never stored or logged (PITFALLS C4) |
| T-02-03 | Elevation of Privilege | Role read from JWT instead of DB | mitigate | get_current_user loads User row from DB; role never trusted from token payload (PITFALLS Anti-Pattern 3) |
| T-02-04 | Spoofing | Unverified account login | mitigate | Login returns 403 until is_email_verified (D-01, strict block) |
| T-02-05 | Tampering | Verification token guessing/replay | mitigate | urlsafe random token, single-use (used_at), 24h expiry |
| T-02-06 | Information Disclosure | User enumeration via distinct register/login errors | accept | v1 school intranet; generic-enough messages, low-value target |
</threat_model>
