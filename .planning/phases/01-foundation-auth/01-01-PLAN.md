## Phase Goal

**As a** library system operator, **I want to** start the full containerized stack with one command and prove a real request flows from the browser through Nginx, FastAPI, and SQLAlchemy to PostgreSQL and back, **so that** every later feature has a verified end-to-end foundation to build on.

<objective>
Build the Walking Skeleton: the thinnest possible end-to-end vertical slice of the entire stack. Scaffold the FastAPI backend (SQLAlchemy 2.0 async + Alembic), the React + Vite frontend (served by Nginx), and the Docker Compose orchestration. Define the foundational data model (User, Book, Copy, library_settings) with the NON-NEGOTIABLE Book/Copy separation, status enums, and soft-delete columns. Prove the stack works by rendering a value read live from PostgreSQL on the landing page.

Purpose: Every downstream phase depends on correct schema and working infrastructure. Schema mistakes (Book/Copy conflation, boolean status, hard deletes) cannot be fixed cheaply after data exists (PITFALLS C1, M5, m2).
Output: A running `docker compose up` stack with health endpoints, the core data model migrated and seeded, and a React page proving the full round trip.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → Nginx → FastAPI | Untrusted HTTP requests enter the API here |
| FastAPI → PostgreSQL | Application data access boundary |
| host env → containers | Secrets (DB password, JWT secret) cross via env/.env |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Information Disclosure | JWT_SECRET / DB password in repo | mitigate | Secrets only in `.env` (gitignored); `.env.example` holds placeholders only (PITFALLS C4) |
| T-01-02 | Denial of Service | backend starting before DB ready | mitigate | pg_isready healthcheck + `depends_on: condition: service_healthy` (PITFALLS M2) |
| T-01-03 | Information Disclosure | CORS misconfig exposing API to any origin | mitigate | `ALLOWED_ORIGINS` explicit list, never `["*"]` with credentials (STACK.md CORS gotcha) |
| T-01-04 | Tampering | health/db endpoint leaking data | accept | Returns only non-sensitive loan_period_days; no PII exposed |
| T-01-SC | Tampering | pip installs (fastapi, sqlalchemy, asyncpg, pyjwt, pwdlib, etc.) | mitigate | All packages are well-known PyPI projects verified in STACK.md research; pin versions in requirements.txt. No [ASSUMED]/[SUS] packages — RESEARCH stack is the audit source |
</threat_model>
