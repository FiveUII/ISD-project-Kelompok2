<objective>
Fine auto-calculation on overdue return — the first vertical slice of Phase 4.

When a librarian returns an overdue loan, the system automatically creates a Fine record without manual input (FINE-01). The Fine model, Alembic migration, Pydantic schemas, and the updated return endpoint form a complete end-to-end slice: action (return) → computation (days overdue × rate) → persistence (fines table).

Non-overdue returns are unaffected: no fine row is created, and the return endpoint behaves identically to Phase 3 for on-time loans.
</objective>

<context>
**Phase goal:** Overdue fines are calculated and tracked automatically on return; librarians can record payments and waivers; students receive proactive email reminders before and after due dates.

**What this plan delivers:** The Fine data layer (model + migration + schemas) and the integration of fine creation into the existing return endpoint. No fine management UI yet — that is Plan 02.

**Key existing files to read before touching anything:**
- `backend/app/routers/loans.py` — return_loan() PATCH handler to extend
- `backend/app/models/library_settings.py` — fine_rate_per_day field (Numeric 6,2)
- `backend/app/models/loan.py` — Loan model FK structure
- `backend/app/models/__init__.py` — import registration pattern
- `backend/alembic/versions/0005_loans_table.py` — migration chaining pattern (down_revision="0005")

**Fine rate source:** `library_settings.fine_rate_per_day` (default 0.25). Never hardcoded. Read from the settings row (id=1), fall back to Decimal("0.25") if no settings row.

**Overdue computation:** `days_overdue = ceil((returned_at - due_date).total_seconds() / 86400)`. Use `math.ceil` to round partial days up. Fine amount = `days_overdue * fine_rate_per_day` (Decimal arithmetic to avoid float precision issues).

**Fine status enum:** 3 values — `unpaid` (default on creation), `paid`, `waived`.
</context>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → PATCH /api/librarian/loans/{id}/return | Librarian-authenticated request; fine amount computed server-side only |

## STRIDE Register

| ID | Threat | Category | Disposition | Mitigation |
|----|--------|----------|-------------|------------|
| T-04-01 | Client sends manipulated loan_id to trigger fine creation on a non-overdue loan | Tampering | Mitigate | Fine amount computed entirely from DB timestamps (due_date, returned_at) — client has no input into fine amount or days_overdue |
| T-04-02 | Fine amount computed from attacker-controlled fine_rate_per_day | Tampering | Accept | fine_rate_per_day is read from library_settings (DB row id=1), not from the request; only librarians can modify settings via admin actions |
| T-04-03 | Negative fine amount if returned_at < due_date (non-overdue) | Tampering | Mitigate | Guard: only create Fine row when days_overdue > 0; non-overdue returns skip fine creation entirely |
</threat_model>
