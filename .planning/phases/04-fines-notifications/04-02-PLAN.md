<objective>
Fine management API + librarian fines UI — FINE-02 (mark paid) and FINE-03 (waive with reason).

A librarian opens /librarian/fines, sees all outstanding fines in a table (loan info, borrower, amount, status), and can mark each as paid or waived with a single action. The waive action collects a reason note via a dialog. Both actions are immediate and reflected in the UI without a page reload.
</objective>

**FineDetailResponse:** Fines list needs joined loan/borrower/book info for the table. Eager-load via selectinload: `Fine.loan → Loan.borrower`, `Fine.loan → Loan.copy → Copy.book`.

**Waive reason:** `PATCH /api/librarian/fines/{id}/waive` accepts `{"reason": "string"}` body. `reason` is required (non-empty string).

**Pagination:** GET /api/librarian/fines?page=1&page_size=20&status=unpaid (status filter optional). Default: all fines, newest first.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → PATCH /api/librarian/fines/{id}/pay | Librarian-authenticated; fine_id from path |
| Client → PATCH /api/librarian/fines/{id}/waive | Librarian-authenticated; reason from body |

## STRIDE Register

| ID | Threat | Category | Disposition | Mitigation |
|----|--------|----------|-------------|------------|
| T-04-04 | Student calls pay/waive endpoint | Elevation of Privilege | Mitigate | fines_router uses `dependencies=[Depends(require_librarian)]` at router level — students get 403 |
| T-04-05 | Waive reason is empty string or whitespace | Tampering | Mitigate | Pydantic validator: `reason: str` with `@field_validator("reason") def reason_not_empty(...)` — rejects blank reasons |
| T-04-06 | Fine double-paid or double-waived | Tampering | Mitigate | 409 guard: if fine.status != "unpaid" raise HTTPException(409, "Fine already settled") |
| T-04-07 | Librarian pays a fine that belongs to a different library's record | Info Disclosure | Accept | Single-library system (REQUIREMENTS.md out-of-scope: multi-branch); all fines are in the same DB |
</threat_model>

         - `LoanBriefForFine(BaseModel, from_attributes=True)`: `id: int`, `due_date: datetime`, `returned_at: datetime | None`, `borrower: StudentBriefResponse`, `book: BookBriefResponse` — reuse `StudentBriefResponse` and `BookBriefResponse` from `schemas/loans.py`

      2. Create `backend/app/routers/fines.py`:
         - `fines_router = APIRouter(prefix="/librarian/fines", tags=["fines"], dependencies=[Depends(require_librarian)])`
         - Eager load options: `FINE_EAGER_OPTIONS = [selectinload(Fine.loan).selectinload(Loan.borrower), selectinload(Fine.loan).selectinload(Loan.copy).selectinload(Copy.book)]`
         - Helper `_fine_to_detail(fine: Fine) -> FineDetailResponse`: attaches `fine.loan.book = fine.loan.copy.book` before model_validate (same pattern as `_loan_to_response`)
         - `GET ""` → list fines: optional `status: str | None = Query(None)`, `page: int = Query(1, ge=1)`, `page_size: int = Query(20, ge=1, le=100)`. Filter by status if provided. ORDER BY created_at DESC. Return `FinesListResponse`.
         - `PATCH "/{fine_id}/pay"`: load fine, 404 if missing, 409 if `fine.status != "unpaid"`, set `fine.status = "paid"`, commit, return `FineDetailResponse`
         - `PATCH "/{fine_id}/waive"`: load fine + `data: WaiveRequest`, 404 if missing, 409 if `fine.status != "unpaid"`, set `fine.status = "waived"` and `fine.waiver_reason = data.reason`, commit, return `FineDetailResponse`

      3. Register in `backend/app/main.py`:
         - Add `from app.routers import fines` import
         - Add `app.include_router(fines.fines_router, prefix="/api")` after the loans router lines
