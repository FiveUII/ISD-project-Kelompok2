<objective>
Email notification service with APScheduler — NOTIF-01 (due-date reminder) and NOTIF-02 (overdue alert).

The scheduler runs inside the FastAPI process and polls for loans needing notifications once per day. Students receive a reminder email a configurable number of days before their loan is due, and an overdue alert when their loan passes the due date. Duplicate sends are prevented via timestamp flags on the Loan model. The email implementation follows the existing dev pattern: log to stdout rather than SMTP (same as send_verification_email and send_password_reset_email in email_service.py).
</objective>

**Scheduler job interval:** Daily (IntervalTrigger with hours=24). Also fires once at startup (trigger job immediately after scheduler.start()).

**Deduplication strategy:** Add `reminder_sent_at: Mapped[datetime | None]` and `overdue_sent_at: Mapped[datetime | None]` as nullable DateTime columns to the Loan model. Alembic migration 0007 adds these columns. The notification job filters: reminder candidates = `returned_at IS NULL AND reminder_sent_at IS NULL AND due_date >= now() AND due_date <= now() + timedelta(days=reminder_days_before)`; overdue candidates = `returned_at IS NULL AND overdue_sent_at IS NULL AND due_date < now()`.

**STATE.md blocker noted:** "Confirm APScheduler + FastAPI separate-container integration pattern before Phase 4 execution." This plan runs APScheduler inside the FastAPI container (in-process, not a separate container), which avoids the Docker complexity concern. The in-process pattern is correct for v1 scope.
</context>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Scheduler job → DB | Server-side only; no external input; queries are read-then-write within a single async session |
| Email service → Stdout (dev) | No external SMTP in v1; no credentials to protect |

## STRIDE Register

| ID | Threat | Category | Disposition | Mitigation |
|----|--------|----------|-------------|------------|
| T-04-08 | Scheduler sends duplicate reminder/overdue emails if job runs multiple times before DB commit | Tampering | Mitigate | reminder_sent_at / overdue_sent_at flags: job sets flag and commits before processing next loan; filter excludes already-flagged loans |
| T-04-09 | Scheduler crashes and suppresses exceptions silently, masking notification failures | Denial of Service | Mitigate | Wrap job body in try/except; log errors via `logging.exception("Notification job failed")` so failures are visible in container logs |
| T-04-10 | APScheduler persists job state to disk and accumulates missed jobs after downtime | DoS (resource) | Accept | Use `misfire_grace_time=3600` and no persistent job store (in-memory only). Missed jobs are skipped rather than accumulated — acceptable for daily email reminders |
</threat_model>
