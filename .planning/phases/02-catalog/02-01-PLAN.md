# Plan 01: Dev Infrastructure — shadcn Init, Path Alias, Nav Shell, Alembic 0003

**Phase:** 2 — Catalog
**Wave:** 0 — Dev Infrastructure (blocks everything)
**Depends on:** Nothing
**Requirements satisfied:** CATL-01 (partial — search indexes), CATS-01 (partial — route shell for catalog page)
**Mode:** mvp

## Goal

shadcn/ui is initialized with the `@/*` path alias, the authenticated layout shell (AppLayout + NavBar) wraps catalog and librarian routes in App.tsx, and Alembic migration 0003 adds the catalog search indexes.

## Threat Model

- Auth pages (login, register, etc.) must remain OUTSIDE the AppLayout shell — these are public routes and must not require authentication.
- Route guard in AppLayout must redirect unauthenticated users to `/login` using `useAuthStore` — do NOT expose catalog or librarian routes publicly.
- Librarian-only route guard (`/librarian/*`) must redirect students to `/catalog`, NOT to `/login` — students are authenticated, just unauthorized.

## Context

Wave 0 is a pure setup plan. It unblocks both the backend (Plan 02) and frontend (Plan 03) from proceeding in parallel. The three deliverables are independent of each other but all required before any catalog UI can be built:

1. **Path alias + shadcn init**: RISK-03 identified that shadcn requires `@/*` alias before `npx shadcn@latest init`. Running init without the alias causes all generated component imports to break.
2. **AppLayout + NavBar**: D-10 requires a shared nav shell wrapping all authenticated pages. Plan 03 builds catalog pages that nest inside this shell — the shell must exist first.
3. **Alembic 0003**: Search indexes on `books.title` and `books.author` improve ILIKE query performance. Can be applied before routes exist.

## Tasks

### Task 1: Configure `@/*` Path Alias and Initialize shadcn/ui

**Why:** RISK-03 is a hard blocker — shadcn components import from `@/components/ui/...` and fail without the alias. The alias must be in both `vite.config.ts` (runtime resolution) and `tsconfig.json` (TypeScript type resolution). shadcn `init` MUST run AFTER the alias is in place, and the component adds MUST run after init.

**Files:**
- `frontend/package.json` (add `@types/node` devDependency)
- `frontend/vite.config.ts`
- `frontend/tsconfig.json`
- `frontend/components.json` (created by shadcn init)
- `frontend/src/components/ui/` (populated by shadcn add)

**Steps:**
- [ ] In the `frontend/` directory, run: `npm install -D @types/node`
- [ ] Update `frontend/vite.config.ts` — add `import path from "path"` at the top and add `resolve: { alias: { "@": path.resolve(__dirname, "./src") } }` inside `defineConfig`. Preserve the existing `plugins` and `server` proxy config exactly.
- [ ] Update `frontend/tsconfig.json` — add `"baseUrl": "."` and `"paths": { "@/*": ["./src/*"] }` inside `"compilerOptions"`. Do not remove any existing keys.
- [ ] In the `frontend/` directory, run: `npx shadcn@latest init` with these answers: Style = New York, Base color = Neutral, CSS variables = Yes. Accept all file creation prompts.
- [ ] Run the single combined add command: `npx shadcn@latest add button input label table badge dialog card separator skeleton alert`
- [ ] Run `npm install @tanstack/react-table` (required for BookDataTable in Plan 03)
- [ ] Verify: `ls frontend/src/components/ui/` lists button.tsx, input.tsx, label.tsx, table.tsx, badge.tsx, dialog.tsx, card.tsx, separator.tsx, skeleton.tsx, alert.tsx

### Task 2: Build AppLayout and NavBar Components

**Why:** D-10 requires all authenticated pages to render inside a shared shell with a top navbar. The shell component is the router wrapper — catalog pages (Plan 03) import and depend on it existing. Building it now as a pure UI component (no API calls) is safe in Wave 0.

**Files:**
- `frontend/src/components/AppLayout.tsx`
- `frontend/src/components/NavBar.tsx`

**Steps:**

**NavBar (`frontend/src/components/NavBar.tsx`):**
- [ ] Import `Link`, `useLocation` from `react-router-dom`; import `useAuthStore` from `../store/auth`
- [ ] NavBar is `h-14` (`56px`), `bg-white`, `border-b border-gray-200`, full-width
- [ ] Inner content: `max-w-7xl mx-auto px-6 flex items-center justify-between h-full`
- [ ] Left side: Logo link — `<Link to="/catalog">` wrapping text "Library" with classes `font-semibold text-gray-900`
- [ ] Center/left nav links: render based on `user?.role`:
  - ALL authenticated users: "Catalog" → `/catalog`
  - `role === "librarian"` additionally: "Manage Books" → `/librarian/books`
  - Active link style (use `useLocation` to compare pathname): `text-blue-600 font-semibold border-b-2 border-blue-600`
  - Inactive link style: `text-gray-600 hover:text-gray-900 text-sm font-semibold`
- [ ] Right side: logout button — `text-gray-500 hover:text-gray-700 text-sm` — calls `logout()` from `useAuthStore` then navigates to `/login` via `useNavigate`
- [ ] Use `text-sm font-semibold` for ALL nav link text (per typography contract: label weight is 600/semibold)

**AppLayout (`frontend/src/components/AppLayout.tsx`):**
- [ ] Import `Navigate`, `Outlet` from `react-router-dom`; import `useAuthStore` from `../store/auth`
- [ ] Accept a prop `requireLibrarian?: boolean` (defaults to false)
- [ ] Auth guard: if `!token`, return `<Navigate to="/login" replace />`
- [ ] Role guard: if `requireLibrarian && user?.role !== "librarian"`, return `<Navigate to="/catalog" replace />`
- [ ] Render: `<div className="min-h-screen bg-gray-50"><NavBar /><main><Outlet /></main></div>`
- [ ] The `<main>` element has no padding — individual pages apply `max-w-7xl mx-auto px-6 py-8` themselves

### Task 3: Wire Routes in App.tsx and Create Alembic Migration 0003

**Why:** App.tsx must nest catalog/librarian routes inside AppLayout with appropriate guards (D-07). Alembic 0003 adds `ix_books_title` and `ix_books_author` indexes that improve ILIKE search performance (D-04) — these are structural and safe to add before routes exist.

**Files:**
- `frontend/src/App.tsx`
- `backend/alembic/versions/0003_catalog_indexes.py`

**Steps:**

**App.tsx updates:**
- [ ] Import `AppLayout` from `./components/AppLayout`
- [ ] Import placeholder page components using lazy imports or simple inline stubs — since catalog pages don't exist yet, create stub route placeholders: the route structure must be in place so Plan 03 pages slot in without changing routing. Use a simple `<div>Coming soon</div>` placeholder component inline for now.
- [ ] Add routes wrapped in `<Route element={<AppLayout />}>`:
  - `<Route path="/catalog" element={<div>Catalog coming soon</div>} />`
  - `<Route path="/librarian/books" element={<div>Manage Books coming soon</div>} />`
  - `<Route path="/librarian/books/new" element={<div>Add Book coming soon</div>} />`
  - `<Route path="/librarian/books/:id" element={<div>Book Detail coming soon</div>} />`
- [ ] Add a nested route group for librarian-only routes using `<Route element={<AppLayout requireLibrarian />}>` wrapping `/librarian/*` routes. This means `/librarian/books`, `/librarian/books/new`, `/librarian/books/:id` all use `requireLibrarian={true}`.
- [ ] Keep all existing auth routes (`/`, `/register`, `/login`, `/verify-email`, `/forgot-password`, `/reset-password`) outside the AppLayout wrapper — they must remain public.

**Alembic migration 0003:**
- [ ] Create `backend/alembic/versions/0003_catalog_indexes.py`
- [ ] Set `revision: str = "0003"` and `down_revision: Union[str, None] = "0002"` (chains from 0002 per research)
- [ ] `upgrade()`: call `op.create_index("ix_books_title", "books", ["title"])` then `op.create_index("ix_books_author", "books", ["author"])`
- [ ] `downgrade()`: call `op.drop_index("ix_books_author", table_name="books")` then `op.drop_index("ix_books_title", table_name="books")`
- [ ] Add a docstring: "Add search indexes on books.title and books.author for ILIKE catalog search performance."
