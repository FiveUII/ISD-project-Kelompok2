## Spacing Scale

Declared values (multiples of 4 only):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps, badge internal padding |
| sm | 8px | Compact element spacing, input internal padding |
| md | 16px | Default element spacing, card padding, form field gaps |
| lg | 24px | Section padding within a page, gap between card rows |
| xl | 32px | Layout content area padding, gap between major sections |
| 2xl | 48px | Page vertical rhythm — between page header and content |
| 3xl | 64px | Not used in Phase 2 |

Exceptions:

- Touch target minimum: 44px height for all interactive controls (Button, row action icons). Use `h-11` (44px) Tailwind class on small icon buttons. *Source: WCAG 2.5.5 touch target guidance.*
- Nav bar height: 56px (`h-14`). Fixed value, not on the 8pt scale but acceptable for nav chrome.

## Typography

| Role | Size | Weight | Line Height | Tailwind Class |
|------|------|--------|-------------|----------------|
| Body | 14px | 400 (regular) | 1.5 | `text-sm` |
| Label | 14px | 500 (medium) | 1.4 | `text-sm font-medium` |
| Heading | 20px | 600 (semibold) | 1.2 | `text-xl font-semibold` |
| Display | 28px | 700 (bold) | 1.2 | `text-3xl font-bold` |

Notes:
- Body at 14px/1.5 matches Phase 1 established pattern (`text-sm` throughout auth pages).
- Display (28px) is reserved for page titles only: "Manage Books", "Book Catalog".
- Heading (20px) is for section titles: "Add Book", "Copies", column group headers.
- Label (14px/500) is for all form labels, table column headers, and nav links.
- Maximum 2 font weights in any single view: regular (400) + either medium (500) or semibold (600) depending on context. Bold (700) appears only in page-level headings.

## Color

All values reference Tailwind's neutral palette, continuing the pattern established in Phase 1.

| Role | Tailwind Token | Usage |
|------|---------------|-------|
| Dominant (60%) | `bg-gray-50` | Page background, app shell background |
| Secondary (30%) | `bg-white` | Cards, nav bar, table rows, form containers, sidebar (if added later) |
| Accent (10%) | `bg-blue-600` / `text-blue-600` | Reserved-for list below |
| Destructive | `bg-red-600` / `text-red-700` | Destructive actions and error states only |

**Accent reserved for (explicit list — accent ONLY goes on these elements):**

1. Primary CTA buttons: "Add Book", "Fetch Details", "Save Changes", "Add Copy"
2. Active nav link indicator (left border or underline on active route)
3. Availability badge when count > 0: `bg-blue-100 text-blue-700`
4. Pagination current-page indicator
5. Focus ring on interactive inputs: `ring-blue-500`

Accent is NOT used on: table row hover, secondary buttons, destructive confirmations, status labels other than availability.

**Status color map (for Copy status badges):**

| Status | Background | Text | Tailwind |
|--------|-----------|------|---------|
| available | `bg-green-100` | `text-green-700` | — |
| on_loan | `bg-yellow-100` | `text-yellow-700` | — |
| lost | `bg-red-100` | `text-red-700` | — |

**Availability badge for student search results:**

- Count > 0: `bg-green-100 text-green-700` — "3 available"
- Count = 0: `bg-gray-100 text-gray-500` — "0 available"

## Interaction Contracts

### ISBN Fetch Flow (CATL-02)

1. Librarian types ISBN in the ISBN field.
2. Librarian clicks "Fetch Details" button (not auto-triggered on blur or change).
3. Button enters "Fetching..." state (disabled, spinner icon).
4. On success: title, author, description fields are filled. A green Alert renders: "Details filled from Open Library. Review and save." Button returns to normal.
5. On no-result (404 from Open Library): An inline Alert (variant: warning) renders: "No book found for this ISBN. Fill in the details manually." Fields remain blank and editable.
6. On network failure / timeout: An inline Alert (variant: destructive) renders: "Service unavailable — fill in the details manually." Fields remain blank and editable.
7. After any fetch, all fields remain editable — librarian can override auto-filled values.

### Search Debounce / Submit (CATS-01)

- Search is NOT real-time as-you-type. Submit fires on:
  - "Search" button click, OR
  - Enter key while search input is focused.
- Query parameter `q` drives TanStack Query's queryKey. Navigation updates the URL: `/catalog?q=hemingway&page=1`.
- Empty query (`q=""`) shows the no-query state, not an empty results state.

### Soft Delete Confirmation Pattern

- "Delete" row action opens a shadcn Dialog (not a browser `confirm()`).
- Dialog contains: title, description with consequences, a red destructive "Delete" Button, and a "Cancel" Button.
- On confirm: mutation fires, row disappears, success toast shown.
- On cancel: dialog closes, no change.

### Mark as Lost Confirmation Pattern

- Same Dialog pattern as soft delete.
- Copy row updates status badge to "Lost" and the action button disappears.

### DataTable Sort (D-09)

- Sortable columns: Title, Author, ISBN, Available, Copies.
- Sort state is client-side (TanStack Table). URL does not encode sort.
- Clicking a column header cycles: asc → desc → unsorted.
- Default sort: Title ascending.

### Pagination (D-05)

- 20 results per page.
- Controls: "Previous" button (disabled on page 1) + "Page N" label + "Next" button (disabled on last page).
- URL encodes page: `?q=...&page=2`.
- TanStack Query uses `keepPreviousData: true` so the previous page remains visible while next page loads.

## Layout Shell

Phase 2 introduces the shared authenticated layout shell (D-10).

### Shell Structure

```
┌─────────────────────────────────────────────┐
│  [Logo/Name]   [Nav links]      [User/Logout]│  ← Top navbar, h-14 (56px), bg-white, border-b
├─────────────────────────────────────────────┤
│                                             │
│   Page content area                         │  ← bg-gray-50, min-h remaining viewport
│   max-w-7xl mx-auto px-6 py-8              │
│                                             │
└─────────────────────────────────────────────┘
```

### Nav Link Rules

| User Role | Visible Nav Links |
|-----------|------------------|
| student | "Catalog" → `/catalog` |
| librarian | "Catalog" → `/catalog`, "Manage Books" → `/librarian/books` |

- Active link: `text-blue-600 font-medium` + `border-b-2 border-blue-600` underline indicator.
- Inactive link: `text-gray-600 hover:text-gray-900`.
- Logo/name: "Library" in `font-bold text-gray-900`, links to `/catalog`.
- Logout: Right-aligned, text button `text-gray-500 hover:text-gray-700`, clears Zustand auth store and redirects to `/login`.

### Route Guard

All routes under the shell (`/catalog`, `/librarian/*`) require authentication. If `useAuthStore()` returns no token, redirect to `/login`. The `/librarian/*` routes additionally check `user.role === "librarian"` — redirect to `/catalog` if a student navigates there directly.

## Accessibility Baseline

- All interactive elements have visible focus rings (shadcn default `ring-2 ring-blue-500`).
- All form inputs have associated `<label>` elements (via shadcn Label component or explicit `htmlFor`).
- All icon-only buttons have `aria-label` text (e.g., Edit row action icon: `aria-label="Edit book"`).
- Color is never the sole indicator of status — status badges include text labels alongside color.
- Dialog focus trap is provided by Radix UI (built into shadcn Dialog).
- Table uses semantic `<table>`, `<th scope="col">`, `<td>` markup (shadcn Table default).
