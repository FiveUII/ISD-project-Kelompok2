# Plan 03: Frontend Catalog UI — Pages, Components, and DataTable

**Phase:** 2 — Catalog
**Wave:** 2 — Frontend UI (blocked on Wave 0 for shell + Wave 1 for API contract)
**Depends on:** 02-01 (AppLayout, shadcn), 02-02 (API endpoints and response shapes)
**Requirements satisfied:** CATL-01, CATL-02, CATL-03, CATL-04, CATL-05, CATL-06, CATS-01, CATS-02
**Mode:** mvp

## Goal

All four catalog pages and all helper components are built and wired into App.tsx, delivering the complete student search experience and librarian book management workflow as a working end-to-end vertical slice.

## Threat Model

- **Route guard enforcement (T-03-01):** AppLayout (from Plan 01) handles route guards — this plan does NOT add inline role checks in page components. Pages simply render; the shell redirects unauthorized users before the page mounts.
- **No client-side availability calculation (T-03-02):** The `available_count` value comes from the API response. Pages must NOT recalculate availability from the copies array — the server is the source of truth (D-12).
- **Copywriting contract (T-03-03):** All user-visible strings must match the exact copywriting contract. No paraphrasing. Deviating strings will cause verification to fail.

## Context

This plan is the largest in Phase 2 (13 files). It is split into three tasks by concern: shared components, catalog pages (student-facing + data display), and librarian management pages (forms + mutations). All tasks share no files, so they could theoretically run in parallel within the plan — but since an executor is a single agent, they run sequentially. The ordering is: shared components first (they are imported by pages), then catalog pages, then librarian pages.

**TanStack Query v5 reminders (RISK-04, RISK-05):**
- `useMutation`: use `isPending` not `isLoading`
- `useQuery` with pagination: `placeholderData: keepPreviousData` (imported function, not boolean flag)
- Import: `import { useQuery, useMutation, useQueryClient, keepPreviousData } from "@tanstack/react-query"`

**URL-driven search pattern (from research — copy exactly):**
```typescript
import { useSearchParams } from "react-router-dom"
import { useQuery, keepPreviousData } from "@tanstack/react-query"

const [searchParams, setSearchParams] = useSearchParams()
const q = searchParams.get("q") ?? ""
const page = Number(searchParams.get("page") ?? "1")

const { data, isLoading } = useQuery({
  queryKey: ["books", { q, page, page_size: 20 }],
  queryFn: () => apiClient.get("/books", { params: { q: q || undefined, page, page_size: 20 } }).then(r => r.data),
  placeholderData: keepPreviousData,
})
```
