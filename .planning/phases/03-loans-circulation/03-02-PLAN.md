<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser→GET /api/librarian/loans | Librarian-only endpoint — require_librarian enforced server-side |
| browser→POST /api/librarian/loans/checkout | copy_id and user_id from browser; server validates both |
| student search dropdown | student query and selected user_id from browser |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-06 | Elevation of privilege | Check Out button visibility | mitigate | "Check Out" button rendered only when user.role === 'librarian' (defense-in-depth; server enforces RBAC regardless) |
| T-03-07 | Spoofing | student search dropdown selection | accept | user_id passed to checkout endpoint validated server-side; client cannot elevate via crafted user_id |
| T-03-08 | Tampering | returnLoan mutation | mitigate | server checks loan ownership and returned_at idempotency; client sends loan_id only |
| T-03-09 | Info disclosure | student email in search results | accept | search is librarian-only endpoint; librarians are trusted actors in v1 |
| T-03-SC | Tampering | npm/pip/cargo installs | mitigate | no new npm packages — TanStack Query, shadcn/ui Dialog already installed; no install tasks |
</threat_model>
